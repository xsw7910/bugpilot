# 阶段性成果文档

[adapter_design.md](../adapter_design.md) §9 划分的每个阶段完成后，在此目录留一份
`phase_N.md`。

## 与实施日志的分工

三份文档，三种时间尺度，不要互相复述：

| 文档 | 写什么 | 什么时候读 |
| --- | --- | --- |
| [adapter_design.md](../adapter_design.md) | **计划**：需求、架构、契约、待决问题 | 开工前；改设计时 |
| [implementation_log.md](../implementation_log.md) | **过程**：每一小步的偏差、当时发现的约束、给下一小步的钩子 | 做下一小步前，只读上一条 |
| `phases/phase_N.md` | **结果**：这一阶段最终交付了什么、下游能依赖什么接口、留下什么坑 | 开始新阶段前；做 review 前；几周后回来找「当时为什么这么做」 |

实施日志是流水账，会越来越长且大部分很快过时。阶段文档是**稳定参照**：
后续阶段只需要读它，不必翻完整个日志。

## 一份阶段文档应当包含

1. **交付物** —— 新增/改动的模块、公开接口、测试数
2. **公开契约** —— 下游阶段可以依赖的东西，签名要准确
3. **与计划的净偏差** —— 跨该阶段所有步骤汇总，注明设计文档是否已同步
4. **验收对照** —— 逐条对上 §9 里该阶段的验收标准
5. **已知遗留** —— 明确没做的、未接线的、留给后续阶段的
6. **给后续阶段与 review 的要点** —— 踩过的坑、必须保持绿的测试、易错的假设

不要复制代码，不要复述设计文档已经写清楚的内容。
