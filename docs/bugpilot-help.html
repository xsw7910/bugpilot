bugpilot — Install & Usage Guide

How to install bugpilot, configure Jira once, and run it. bugpilot turns a Jira bug into an AI-ready package, then launches a coding agent to implement the fix — with you in control of what ships. Every command block has a Copy button.

Windows · PowerShell Python 3.10+ Jira Cloud Run from the target repo root

1 · Install

1

Double-click install.cmd

One double-click does everything: it installs Python if you don't have it, installs bugpilot, then runs bugpilot setup — where you enter your Jira email and API token (create one at id.atlassian.com/manage-profile/security/api-tokens), saved to ~/.bugpilot/config.toml. Keep the installer\ folder next to install.cmd; re-run setup anytime with bugpilot setup.

install.cmd  ·  double-click this
installer\  ·  install.ps1 + wheel (leave alone)

2 · Run it

2

From your product repo, run one command

Run from your product repo root, on a clean working tree and on master — the workflow creates a feature branch (feature/JR-12345-…) based on the Jira item number, off your current branch.

your-product-repo
❯ cd C:\path\to\your-product-repo  #C:\sandbox\monorepo
❯ bugpilot JR-12345

Prepares the package, then launches Claude to make the fix. It stops at the commit gate — you review and commit. bugpilot never commits or pushes.

3

Verify

new PowerShell window
❯ bugpilot --help

See the command list? You're installed.

3 · Options

Flags for bugpilot <issue> — replace JR-12345 with your issue key.

bugpilot <issue> options
❯ bugpilot JR-12345 --prepare-only   # just build artifacts, don't launch an agent
❯ bugpilot JR-12345 --copilot        # use Copilot CLI instead of Claude
❯ bugpilot JR-12345 --hint "Fix in FooWidget.cxx: keep selection on tab switch"
❯ bugpilot JR-12345 --jira-comment   # also post one Jira status comment
❯ bugpilot JR-12345 --resume         # keep existing .ai/JR-12345/ artifacts
❯ bugpilot JR-12345 --allow-mock     # demo without Jira credentials
Defaults

Claude launches by default (--prepare-only to skip). Jira comment off by default (--jira-comment to enable). Runs are fresh (--resume to keep artifacts).

4 · All commands (reference)

Every command, grouped. Base commands are copy-ready; comments note the useful flags. Replace JR-12345 with your issue key.

setup & environment
❯ bugpilot setup                        # configure Jira email + token (--hide-token to hide it)
❯ bugpilot doctor                       # check Python, git, ripgrep, Jira, agents, email
❯ bugpilot agent-check                 # Copilot / Claude / gh availability
❯ bugpilot status JR-12345               # step status + generated files for an issue
main workflow
❯ bugpilot JR-12345                      # DEFAULT: prepare, then launch Claude
❯ bugpilot JR-12345 --prepare-only   # artifacts only, no agent
❯ bugpilot JR-12345 --copilot        # use Copilot instead of Claude
❯ bugpilot JR-12345 --jira-comment   # add the pre-commit Jira status comment (off by default)
❯ bugpilot JR-12345 --hint "…"        # point the agent at the fix location
❯ bugpilot JR-12345 --resume         # keep artifacts  |  --fresh (default) re-cleans
❯ bugpilot JR-12345 --include-memory # also reset this issue's shared memory (fresh only)
❯ bugpilot JR-12345 --allow-mock     # demo without Jira  |  --no-mock = default (real)
jira
❯ bugpilot fetch JR-12345                # fetch the issue (real Jira; --allow-mock for demo)
❯ bugpilot jira-validate JR-12345        # fetch + field-mapping check (real Jira only)
❯ bugpilot parse JR-12345                # structured repro / actual / expected / errors
analysis (individual prepare steps)
❯ bugpilot keywords JR-12345             # high / normal / dropped keywords
❯ bugpilot search JR-12345               # ripgrep code search + confidence (High/Med/Low)
❯ bugpilot git-context JR-12345          # branch, status, recent history
❯ bugpilot context JR-12345              # build bug_context.md
agent hand-off package
❯ bugpilot prompt JR-12345               # regenerate copilot_task / handoff / team_instructions
❯ bugpilot agent-task JR-12345         # regen task package (--jira-comment to include Jira step)
❯ bugpilot agent-instructions JR-12345 # refresh per-issue team rules
results & memory
❯ bugpilot check-results JR-12345        # verify agent output files (--strict to fail if missing)
❯ bugpilot manual-result JR-12345        # manual-fix templates (--overwrite to replace)
❯ bugpilot summarize-results JR-12345    # build result summary (--jira-comment posts a comment)
❯ bugpilot review-package JR-12345       # final review prompt
❯ bugpilot memory search JR-12345        # find similar past issues (or a free-text query)
❯ bugpilot memory add JR-12345           # create / refresh shared memory entry
❯ bugpilot memory update JR-12345        # fold the result summary into memory
notifications
❯ bugpilot jira-comment-draft JR-12345   # local draft (root cause + change summary)
❯ bugpilot jira-comment JR-12345         # preview; add --execute to post exactly one comment
❯ bugpilot notify JR-12345               # write email draft + .eml; add --execute to send
❯ bugpilot retry-prompt JR-12345         # second-attempt prompt + user_feedback.md

cleanup
❯ bugpilot clean JR-12345                # delete .ai/JR-12345/  (--include-memory also removes memory)

5 · Configuration

Where settings come from

Jira credentials resolve in this order: environment variables → ~/.bugpilot/config.toml → fixed company URL. Run bugpilot setup to write the config file; use env vars to override per-shell.

~/.bugpilot/config.toml
jira_email = "you@your-company.com"
jira_token = "your-api-token"
Environment variables

Jira: JIRA_BASE_URL JIRA_EMAIL JIRA_TOKEN.  Auto Jira comment from summarize-results: BUGPILOT_AUTO_JIRA_COMMENT=true.  Email: BUGPILOT_EMAIL_FROM/TO plus Graph (GRAPH_TENANT_ID/CLIENT_ID/CLIENT_SECRET) or SMTP (SMTP_HOST/PORT/USERNAME/PASSWORD).  Agent: BUGPILOT_CLAUDE_COMMAND / BUGPILOT_CLAUDE_ARGS (and Copilot equivalents).

Security note

For now the API token is saved in plaintext in config.toml (file permissions tightened where the OS allows). Treat that file as a secret; don't commit or share it.

6 · Troubleshooting

  • “bugpilot is not recognized” — close and reopen PowerShell (PATH was updated during install). Still missing? python -m pipx ensurepath, then reopen. (exe users: add its folder to PATH or use the full path.)
  • “Python was not found” / installer says no Python — let install.cmd install it via winget (say Yes), or install Python 3.12 yourself (Install step 1) and reopen the terminal.
  • Installer can't find a wheel — the bugpilot-*.whl must sit in the installer\ folder, next to install.ps1.
  • “running scripts is disabled” / a security prompt — use install.cmd (double-click); it handles the execution policy. exe first run → SmartScreen → More info → Run anyway.
  • setup: “Authentication failed” — wrong email or token, or the token was revoked. Create a fresh token and re-run bugpilot setup.
  • Jira “not found or not accessible” — the issue key is wrong, or your account can't view that project. Open <JIRA_URL>/browse/JR-12345 in a browser to confirm.
  • Fix didn't happen — if you ran --prepare-only, no agent was launched. Re-run without it, or open the agent yourself and paste: Read .ai/JR-12345/agent_task.md and complete the workflow.

7 · Update / uninstall

Update: re-run install.cmd with the newer bugpilot-*.whl (it reinstalls in place). exe users: replace bugpilot.exe with the new one. Your ~/.bugpilot/config.toml is kept.

Uninstall: pipx uninstall bugpilot (or delete bugpilot.exe). Delete ~/.bugpilot/config.toml too if you want your saved Jira credentials gone.

bugpilot is prepare-and-hand-off: it builds a reviewable package and launches an agent that stops at the commit gate. It never commits, pushes, merges, opens PRs, or changes Jira fields — you stay in control of what ships.
